# ADR 0002：采用固定壳层与注册式估值模块

- 状态：提议中
- 日期：2026-10-24

## 背景

Codex 生成的 schema 1.1 数据卡已经包含完整章节，但前端只实现了旧 HTML 控件协议，导致情景图、合理区间、仓位档位、溢价环图、收益图和风险等级出现静默丢失。

不同估值路径需要的分析不同，但现有实现用自由 block 和中文标题启发式决定布局，既无法保证扩展性，也无法保证表格长文本下的稳定排版。

## 决策

1. 设计 schema 1.2，作为 Codex 输出、后端导入和前端渲染的唯一契约。
2. section 使用固定 `role` 决定布局，中文标题只负责显示。
3. 路径专用分析通过受控 `model_modules[]` 和 `role: "model_analysis"` 扩展。
4. schema 1.2 只接受 canonical block，旧 block 由历史适配器处理。
5. 表格列声明 `label`、`value`、`assessment`、`note` 等语义角色，前端决定列宽、换行、折叠和移动端布局。
6. 数值事实继续保留在 `markets[]`，`presentation` 负责语义展示；后续校验必须保证两者同源同值。
7. schema 1.0/1.1 只读兼容，新估值只能生成 1.2。

## 后果

- UI 的页面壳层、block 协议和响应式行为可以稳定下来，同时允许不同估值模型增加专用模块。
- 前端需要新增 canonical block 渲染器、未知 block 错误状态和长文本压力测试。
- 后端需要执行 JSON Schema 之外的市场、区间、合计和一致性校验。
- Codex skill、`scorecard.py`、`rank.py` 和现有 fixture 需要迁移到 1.2。
- 旧数据卡和已发布报告需要经过适配与重审，不能直接按新规则继续参与排名。
