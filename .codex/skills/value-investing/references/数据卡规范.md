# 数据卡规范（schema 1.2）

> 机器契约：[card-v1.2.schema.json](card-v1.2.schema.json)
> 可直接运行的完整示例位于项目仓库的 `schemas/value-investing/examples/card-v1.2.example.json`。

数据卡是 value-investing 的唯一交付物，同时服务排名和 Web 详情。新卡只允许 schema 1.2；1.0/1.1 仅用于历史读取。

## 文件与边界

- 文件名：`{标的名}_{YYYY-MM-DD}.json`。
- 一个标的只写一个文件，A/H 等市场放进 `markets[]`。
- 只输出 JSON，不输出 HTML、Markdown、CSS、SVG 或前端组件名。
- `markets[]` 是核心数字事实源；`presentation` 的重复数值必须通过语义校验。
- 必需数据缺失时终止任务，不生成新卡；新卡 `missing` 必须为空。

## 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | string | 固定 `"1.2"` |
| `analysis_date` | string | `YYYY-MM-DD` |
| `generated_at` | string | 带时区的 ISO 时间 |
| `name` | string | 标的名称 |
| `codes` | object | 市场到证券代码 |
| `asset_type` | string | `stock` / `etf` |
| `path` | string | `stable` / `cyclical` / `financial` / `etf` |
| `model_modules` | array | 本次实际使用的注册模块，必须与 `model_analysis` 章节一致 |
| `industry` | string | 行业 |
| `cycle_stage` | string | 导入/爆发期、平台增长期、成熟期、衰退期之一 |
| `cycle_position` | number | 0–100，缺失时终止 |
| `quality` | object | 质地评级与门槛 |
| `conclusion` | object | 全局 code + label 结论 |
| `macro` | object | 无风险利率、汇率及日期 |
| `markets` | array | 每市场一条 |
| `risks` | array | 风险摘要 |
| `missing` | array | 新卡必须为空 |
| `notes` | string | 口径与限制 |
| `presentation` | object | 页面语义层 |

## 结论

```json
{
  "conclusion": {
    "verdict": {"code": "accumulate", "label": "分批买入"},
    "thesis": "一句话核心逻辑",
    "confidence": {"code": "medium", "label": "中"}
  }
}
```

- `verdict.code`：`buy` / `accumulate` / `watch` / `hold` / `reduce` / `avoid` / `excluded` / `not_applicable`。
- `confidence.code`：`low` / `medium` / `high`。

## 市场数据

每个 `markets[]` 必须包含：

```json
{
  "market": "A",
  "code": "600000.SH",
  "currency": "CNY",
  "price": 50,
  "price_date": "2026-10-24",
  "fair_low": 55,
  "fair_mid": 60,
  "fair_high": 65,
  "valuation": {
    "pe": 6.0,
    "pb": 0.9,
    "dividend_yield_after_tax": 4.5,
    "percentile": 30
  },
  "safety_margin_pct": 16.7,
  "certainty": 75,
  "expected_return": {
    "dividend": 4.5,
    "growth": 4.0,
    "valuation": 5.0,
    "fx": 0,
    "total": 13.5
  },
  "downside": {
    "max_drawdown_pct": -22,
    "scenario": "悲观情景描述"
  },
  "position": {
    "tranches": [
      {"level": 1, "price": 50, "trigger_type": "valuation", "condition": "进入合理买入区", "allocation_pct": 30, "active": true},
      {"level": 2, "price": 46, "trigger_type": "evidence", "condition": "财报确认逻辑未恶化", "allocation_pct": 30, "active": false},
      {"level": 3, "price": 43, "trigger_type": "stabilization", "condition": "价格止跌且中枢未下修", "allocation_pct": 25, "active": false},
      {"level": 4, "price": 40, "trigger_type": "catalyst", "condition": "基本面改善得到验证", "allocation_pct": 15, "active": false}
    ]
  },
  "verdict": {"code": "accumulate", "label": "分批买入"}
}
```

口径：

- 百分比统一用 number，`4.5` 表示 4.5%。
- `safety_margin_pct = (fair_mid − price) / fair_mid × 100`。
- `max_drawdown_pct` 必须为负数。
- `expected_return` 四项相加必须等于 `total`。
- `allocation_pct` 只表示计划买入内部的分批比例，四档合计 100；不估计账户总仓位、基础仓位、目标仓位或标的最大仓位。
- 四档依次为 `valuation`、`evidence`、`stabilization`、`catalyst/reserve`，每档必须写可验证的 `condition`。
- `certainty` 为 0–100。

### ETF 专用字段

`path: "etf"` 时每个 `markets[]` 还必须包含 `etf_metrics`：

```json
{
  "index_code": "EXAMPLE",
  "index_name": "示例指数",
  "weight_method": "top10_market_cap_weighted_harmonic",
  "weight_as_of": "2026-09-30",
  "weight_source": "中证指数官方 closeweight",
  "coverage_pct": 88.0,
  "pb_as_of": "2026-10-23",
  "pb_source": "腾讯港股快照 PB 字段",
  "nav": 1.0,
  "nav_date": "2026-10-23",
  "nav_source": "基金净值接口",
  "premium_discount_pct": 0.0,
  "constituents": [
    {"code": "00001.HK", "name": "示例股票甲", "weight_pct": 50.0, "pb": 0.5},
    {"code": "00002.HK", "name": "示例股票乙", "weight_pct": 38.0, "pb": 8.0}
  ],
  "representative_pb": 0.8415
}
```

- `constituents` 最多记录前十大成分；`coverage_pct` 必须等于 `weight_pct` 合计。
- `representative_pb = coverage_pct / Σ(weight_pct ÷ pb)`，禁止使用算术平均。
- `representative_pb` 必须与 `markets[].valuation.pb` 一致，并明确这是前十大代表值。
- `premium_discount_pct = (price / nav - 1) × 100`；ETF 折溢价与底层 PB 是两个口径。
- `pb_as_of`、`nav_date` 必须与 `price_date` 同日。
- `weight_method` 固定为 `top10_market_cap_weighted_harmonic`。

## Presentation 页面壳层

section 通过固定 `role` 决定布局：

```text
dashboard
quality
cycle
model_analysis
cross_market
valuation
position
expected_return
risks
conclusion
sources
disclaimer
```

要求：

- `id` 唯一且使用小写 kebab-case，例如 `dashboard-a`、`valuation-h`、`expected-return-a`。
- 标题只表达功能，不写 A 股、H 股、A/H 或 AH。
- `dashboard` 只包含一个 `gauges`，固定四项及顺序：`safety_margin`、`percentile`、`dividend`、`certainty`。
- 质量章右侧表格必须依次使用 `value`（结果）与 `assessment`（评价）两列，行数固定为 5，并与左侧五个评分按位置对应；不得重复维度列。
- `cycle` 章节开头必须是 `industry_lifecycle`，其 `stage` 与顶层 `cycle_stage` 一致。
- `path: "cyclical"` 时，第二个 block 必须是 `industry_cycle`，其 `position` 与顶层 `cycle_position` 一致，并按固定映射写入 `phase/direction`：`0–25 recovery/up`、`25–50 upswing/up`、`50–75 pullback/down`、`75–100 downswing/down`。非周期行业可省略第二张图。
- `model_analysis` 与 `valuation` 至少各有一个 `formula`，`cross_market` 可选；公式不得出现在质量、产业周期、仓位、预期收益章节。公式必须带符号式 `latex`、代入式 `substitution` 和自然语言 `explanation`。
- `sources`、`disclaimer` 和 `dashboard` 不要求本章小结。
- 其他业务 section 最后一项必须是 `{"type":"callout","summary":true,...}`。

### A/H 固定结构

```text
dashboard-a / dashboard-h
quality / cycle
cross_market
valuation-a / valuation-h
position-a / position-h
expected-return-a / expected-return-h
risks-a / risks-h
conclusion-a / conclusion-h
sources / disclaimer
```

- `quality`、`cycle`、`cross_market`、`sources`、`disclaimer` 使用 `market: "common"`。
- 单市场卡不得出现 `cross_market` 或其他市场的业务 section。
- `cross_market` 只做溢价分析，不得放估值情景、合理区间、仓位或收益拆解。

## 模型模块注册表

| path | 允许模块 |
|---|---|
| `stable` | `gordon_reverse`、`peg`、`dividend_sustainability`、`dividend_yield` |
| `cyclical` | `normalized_earnings`、`cycle_position`、`pb_roe` |
| `financial` | `pb_roe`、`pev_sensitivity`、`nbv_quality`、`solvency` |
| `etf` | `index_percentile`、`tracking_quality`、`dividend_yield` |

模型只能选择注册模块，不能发明 section role、block 类型或前端组件。

## Block

新卡只允许：

```text
heading, paragraph, callout, bullets, formula, table, grid,
scores, metric_cards, gauges, industry_lifecycle, industry_cycle,
valuation_scenarios,
range_position, position_tiers, return_stack,
premium_donut, risk_cards
```

任何其他 block（包括旧 `scenario_bars`、`range_bar`、`steps`、`donut`）都不能写入新卡。

## 同源同值

以下必须一致：

- `markets[].price` 与 `valuation_scenarios.current_price`、`range_position.current_price`
- `markets[].fair_low/mid/high` 与 `range_position`
- `markets[].expected_return` 与 `return_stack`
- `markets[].position.tranches` 与 `position_tiers.items`
- `markets[].certainty`、`safety_margin_pct`、`valuation.percentile` 与 dashboard 对应 gauge
- ETF 的 `markets[].valuation.pb`、`etf_metrics.representative_pb` 与前十大归一化调和平均结果
- ETF 的 `markets[].price`、`etf_metrics.nav` 与 `premium_discount_pct`
- 顶层风险与风险章节的核心结论

## 校验

```bash
python3 scripts/scorecard.py validate data/标的名_YYYY-MM-DD.json
python3 scripts/scorecard.py list --dir data
```

`scorecard.py` 与后端 `card_contract.py` 使用同一份 [card-v1.2.schema.json](card-v1.2.schema.json)，并额外执行跨字段语义检查。
