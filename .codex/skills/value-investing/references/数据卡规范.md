# 数据卡规范（data/*.json）

数据卡是估值 skill 的唯一交付物，同时服务「投资性价比排序」和 Web 详情页。不要再生成或解析 HTML；自然语言只用于说明，图表、表格与仓位档位都必须有结构化字段。

## 一、位置与命名

- 目录：当前工作区的 `data/`。
- 文件名：`{标的名}_{YYYY-MM-DD}.json`，日期用分析日期。
- 一个标的（含 A+H）只写一个文件；市场字段放进 `markets[]`。
- `presentation.sections[]` 保存 Web 详情页所需的全部章节和控件。
- ETF 与个股使用同一套结构，`asset_type` 分别为 `etf` / `stock`。

## 二、顶层字段

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `schema_version` | string | 固定 `"1.1"` |
| `analysis_date` | string | `YYYY-MM-DD` |
| `generated_at` | string | 写卡时间，带时区 |
| `name` | string | 标的名称 |
| `codes` | object | `{"A":"601318.SH","H":"02318.HK"}` |
| `asset_type` | string | `stock` / `etf` |
| `path` | string | `stable` / `cyclical` / `financial` / `etf` |
| `industry` | string | 行业 |
| `cycle_stage` | string | 产业周期阶段 |
| `cycle_position` | number/null | 0–100 |
| `quality` | object | 质地评级与门槛 |
| `conclusion` | object | 全局结论 |
| `macro` | object | 无风险利率与汇率 |
| `markets` | array | 每个上市市场一项 |
| `risks` | array | 主要风险 |
| `missing` | array | 缺失字段 |
| `notes` | string | 口径与置信度 |
| `presentation` | object | Web 详情页章节与控件，见 [报告区块规范.md](报告区块规范.md) |

## 三、核心对象

## 四、`markets[]`

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `market` | string | `A` / `H` / `US` / `CN` |
| `code` | string | 证券代码 |
| `currency` | string | `CNY` / `HKD` / `USD` |
| `price` | number | 现价 |
| `price_date` | string | 现价日期 |
| `fair_low` / `fair_mid` / `fair_high` | number | 合理区间与中枢 |
| `valuation` | object | `{pe, pb, dividend_yield_after_tax, percentile}` |
| `safety_margin_pct` | number | 正数便宜、负数高于中枢 |
| `gauges` | object | `{safety_margin, percentile, dividend, certainty}` |
| `expected_return` | object | 年化收益拆解 |
| `downside` | object | `{max_drawdown_pct, scenario}`，回撤用负数 |
| `position` | object | 仓位比例与买入档位 |
| `verdict` | string | 分市场结论 |

### `expected_return`

| 字段 | 说明 |
|:---|:---|
| `dividend` | 税后股息年化贡献 |
| `growth` | 增长年化贡献 |
| `valuation` | 估值修复年化贡献，可为负 |
| `fx` | 汇率年化贡献或拖累 |
| `total` | 合计年化 |

全部字段都是百分比数值。`28.6` 表示 28.6%。

### `position`

```json
{
  "base_pct": 5,
  "target_pct": 3,
  "cap_pct": 5,
  "tranches": [
    {
      "level": 1,
      "price": 52.19,
      "allocation_pct": 40,
      "active": true
    },
    {
      "level": 2,
      "price": 46,
      "allocation_pct": 30,
      "active": false
    },
    {
      "level": 3,
      "price": 42,
      "allocation_pct": 30,
      "active": false
    }
  ]
}
```

- `target_pct` 是占资产比例。
- `allocation_pct` 是占目标仓位的比例，三档合计必须为 100。
- 不要用一段自然语言描述三档比例；前端不得再次从“加至 3%”等文字猜口径。

## 七、口径硬要求

1. **同源同值**：`markets[]`、`presentation` 和排名字段来自同一次分析，重复数字必须一致。
2. **百分比写 number**：`4.72` 表示 4.72%，不要写 `0.0472` 或 `"4.72%"`。
3. **`safety_margin_pct` 方向**：正数便宜、负数高于中枢。
4. **`downside.max_drawdown_pct` 用负数**。
5. **新估值不允许缺失。** 任一必需数据缺失时必须终止任务，不得写候选卡；`missing` 仅用于读取历史卡，新生成成功卡的 `missing` 必须为空。
6. **一处只有一个真相**：`fair_mid` 是排序中枢；区间中点和正文中枢冲突时重新计算，不留两个值。
7. **百分比不能混口径**：仓位档位必须拆成 `target_position_pct` 与 `allocation_pct`。
8. **收益拆解必须闭合**：分项相加与 `total` 有差异时在 `notes` 说明。
9. **新卡必须是 schema 1.1**；schema 1.0 仅用于读取历史卡。

## 八、校验

```bash
python3 scripts/scorecard.py validate data/中国平安_2026-10-13.json
python3 scripts/scorecard.py list --dir data
```

校验器必须阻止错误进入数据库，而不是让前端猜自然语言。
