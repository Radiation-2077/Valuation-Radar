# 通用数据本地缓存（common/）

第一步「数据收集」的配套规范：**通用数据先查本地，24 小时内的不联网；没命中或过期才去抓，抓完一律回写落盘。**

这样做的原因很实际：无风险利率、汇率这类数据每份报告都要用，重复联网既慢又容易在同一个源上失败，而且一轮分析里前后两次取到不同数值会让报告自相矛盾。本地留一份带时间戳的副本用于复用在有效期内的数据；过期数据不能兜底估值。

## 一、哪些数据进 `common/`

| 进 `common/` | 不进 `common/` |
|:---|:---|
| 与具体标的无关、换只股票还会用到的数据：10 年期国债收益率（中 / 美）、USD/CNY、HKD/CNY、恒生 AH 股溢价指数、LPR、宽基指数估值分位 | 标的自身的现价、市值、财务数据、股东结构——每次现场取，不进缓存 |

判断标准一句话：**换个标的还用同一份数据的，就进 `common/`**。行业平均 PE / PB 属于中间情况——同一个行业会连着看多只股票时值得缓存（如 `industry_pe_银行`），只做一次就别建。

## 二、目录与命名

- 位置：**当前工作区** 的 `common/` 目录（与报告输出同级），首次写入时自动创建，不需要提前建。
- 粒度：一个数据类别一个文件，`common/<key>.json`；key 用小写英文 slug（字母、数字、`.`、`_`、`-`）。
- 已约定的 key：

  | key | 内容 | 建议 ttl |
  |:---|:---|:---|
  | `treasury_10y` | 中美 10 年期国债收益率（无风险利率） | 24h |
  | `fx_rates` | USD/CNY、HKD/CNY 即期 | 12h |
  | `hsahp` | 恒生 AH 股溢价指数 | 6h |
  | `lpr` / `index_pe_hs300` 等 | 后续新增，沿用同样的命名风格 | 24h |

## 三、文件格式

统一 JSON，顶层固定三个字段由脚本维护（`key`、`updated_at`、`ttl_hours`），其余由取数时写入：

```json
{
  "key": "treasury_10y",
  "updated_at": "2026-10-12T20:25:14+08:00",
  "ttl_hours": 24,
  "source": "FRED DGS10 / 中债估值中心",
  "unit": "%",
  "note": "",
  "items": {
    "US10Y": { "value": 4.12, "as_of": "2026-10-10", "source": "FRED DGS10" },
    "CN10Y": { "value": 1.85, "as_of": "2026-10-11", "source": "中债" }
  }
}
```

| 字段 | 含义 |
|:---|:---|
| `key` / `updated_at` / `ttl_hours` | 由脚本写入，**不要手写**；`updated_at` 是本地抓取时间，用来判 24 小时 |
| `source` / `unit` / `note` | 数据来源、单位、口径说明（如「银行间」还是「交易所」） |
| `items` | 具体数值；每个条目带 `value`、`as_of`（数据本身的日期，通常是 T-1）、`source` |
| 其他自定义字段 | 允许，脚本原样保留（例如收益率曲线整条序列、历史数组） |

文件名即 key，因此**只能存当前值**；需要历史序列时放进同一个文件的数组字段（如 `items.CN10Y.history`），不要另建一堆日切文件。

## 四、读写流程（每次做报告都走一遍）

1. **查**：`cache.py get <key>`。
2. **命中**（退出码 0）：直接用 `data`，本轮不再联网。在报告「数据来源」里注明 `common/<key>.json` 与该文件的 `updated_at`。
3. **过期或缺失**（退出码 3 / 4）：按 [联网取数.md](联网取数.md) 的接口抓取；拿到后立刻 `cache.py put` 落盘——**已有文件就地更新，没有的新建**，两种情况都只改同一个 key 的文件。
4. **抓取失败但本地有过期文件**：立即终止，不得继续生成数据卡。过期值只能用于判断哪些远端源异常。
5. **抓取失败且本地也没有**：立即终止并报告缺失字段，不得标「未获取」后继续。

24 小时是默认值，个别数据可以更短：写的时候带 `--ttl`（例如汇率 12、AH 溢价指数 6）。

## 五、脚本用法

```bash
# 读：命中打印 hit=true 且退出码 0；过期退 3；没有退 4（过期 data 仅用于诊断）
python3 scripts/cache.py get treasury_10y

# 写：新建或就地更新，自动补 key / updated_at / ttl_hours，原子替换
python3 scripts/cache.py put treasury_10y --ttl 24 --data '{
  "source": "FRED DGS10 / 中债",
  "unit": "%",
  "items": {
    "US10Y": {"value": 4.12, "as_of": "2026-10-10", "source": "FRED DGS10"},
    "CN10Y": {"value": 1.85, "as_of": "2026-10-11", "source": "中债"}
  }
}'

# 也可以用文件传 payload（结构复杂时更顺手）
python3 scripts/cache.py put fx_rates --ttl 12 --data-file /tmp/fx.json

# 盘点：列出 common/ 下所有文件的新鲜度
python3 scripts/cache.py list
```

脚本路径写作 `scripts/cache.py` 时，前提是当前目录是技能目录；在其他目录运行时请使用实际安装路径，例如 `python3 "$HOME/.codex/skills/value-investing/scripts/cache.py" get treasury_10y`。

## 六、报告里怎么体现

- 「数据来源与免责声明」章节列出本轮用到的 `common/` 文件、各自的 `updated_at` 与来源，让读者能判断新旧。
- 用到缓存数据的结论旁边，如果数据已经接近有效期边缘（比如 20 小时以上）或本轮未更新，加一句口径说明。
- 不要把「本地缓存的取数时间」当成「数据的实际日期」——国债收益率这类指标本身是 T-1，报告里引用 `as_of`。
