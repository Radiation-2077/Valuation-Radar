# Web 报告区块规范（schema 1.2）

`presentation` 只表达 section role、控件类型和数值。前端决定布局、颜色、圆角、tooltip、列宽和响应式。

## Section

```json
{
  "id": "valuation-a",
  "role": "valuation",
  "title": "估值",
  "market": "A",
  "blocks": []
}
```

- `id`：唯一、小写 kebab-case。
- `role`：固定布局语义。
- `title`：只写功能名，禁止 A 股、H 股、A/H、AH。
- `market`：`common` / `A` / `H` / `US` / `CN`。
- `model_analysis` 还必须包含注册过的 `module`；其他 role 不允许带 `module`。
- 除 `dashboard`、`sources`、`disclaimer` 外，最后一项必须是 summary callout。

固定顺序：

```text
dashboard
quality
cycle
model_analysis（可选，可多次）
cross_market
valuation
position
expected_return
risks
conclusion
sources
disclaimer
```

## Dashboard

只能有一个 `gauges` block，固定四项：

```json
{
  "type": "gauges",
  "items": [
    {"key":"safety_margin","label":"安全边际","value":16.7,"display_value":"16.7%","kind":"safety_margin_pct","tone":"pos"},
    {"key":"percentile","label":"估值历史分位","value":30,"display_value":"30%","kind":"percentile","tone":"pos"},
    {"key":"dividend","label":"股息率吸引力","value":65,"display_value":"4.5%","kind":"score_0_100","tone":"acc"},
    {"key":"certainty","label":"确定性","value":75,"display_value":"75%","kind":"certainty","tone":"info"}
  ]
}
```

- 不得混入 heading、paragraph、metric_cards 或 callout。
- `safety_margin` 的 value 与 `markets[].safety_margin_pct` 一致。
- `percentile` 与 `valuation.percentile` 一致；没有数据必须终止，不能写 null。
- `dividend.value` 是 0–100 的吸引力分，`display_value` 才是实际股息率。
- `certainty` 与 `markets[].certainty` 一致。

## 质量 Grid

左栏 `scores` 五维，score 为 0–10 number；右栏只放“结果 / 评价”两列语义表格，固定五行。左侧评分已标出维度，右侧不得重复维度名：

```json
{
  "type": "grid",
  "columns": [
    [
      {"type":"heading","level":3,"text":"质量分项（0–10）"},
      {"type":"scores","items":[
        {"label":"利润现金含量","score":8.0,"tone":"positive"},
        {"label":"资产负债表","score":8.0,"tone":"positive"},
        {"label":"ROE 水平","score":7.5,"tone":"positive"},
        {"label":"护城河强度","score":8.0,"tone":"positive"},
        {"label":"生存能力","score":8.5,"tone":"positive"}
      ]}
    ],
    [
      {"type":"heading","level":3,"text":"关键指标"},
      {"type":"table","variant":"comparison","columns":[
        {"key":"value","label":"结果","role":"value"},
        {"key":"assessment","label":"评价","role":"assessment"}
      ],"rows":[]}
    ]
  ]
}
```

质量分数不再写字符串，也不写 `width`；进度条由前端按 `score × 10` 计算。质量表的五行业务键只能是 `value` 与 `assessment`，行与左侧五维按位置对应。

## Cycle

产业生命周期与景气周期是两个独立图层。`cycle` 章节的第一项必须是生命周期图：

```json
{
  "type": "industry_lifecycle",
  "stage": "成熟期"
}
```

- `stage` 只能是 `导入/爆发期`、`平台增长期`、`成熟期`、`衰退期`。
- `stage` 必须等于顶层 `cycle_stage`。
- 前端固定显示四个阶段，并用当前位置线标明当前阶段。

`path: "cyclical"` 时，第二项必须是景气周期曲线：

```json
{
  "type": "industry_cycle",
  "position": 55,
  "phase": "pullback",
  "direction": "down"
}
```

- `position` 必须是 0–100 的 number，并等于顶层 `cycle_position`。
- `phase` / `direction` 必须与位置一致：`0–25 recovery/up`、`25–50 upswing/up`、`50–75 pullback/down`、`75–100 downswing/down`。
- 前端用正弦曲线、当前点、方向箭头和当前状态标签展示周期位置，必须说明当前是在回暖、上行、回落还是探底。
- 缺失 `phase` 或 `direction` 时不得根据 `position` 在前端猜测；新卡必须终止并补齐判断。
- 非周期行业可以省略 `industry_cycle`；不得用一个控件混合生命周期与景气周期。
- 不得改用公式、段落或只有颜色而没有当前位置的图表替代。

## Table

列必须使用语义角色，行使用对象：

```json
{
  "type": "table",
  "variant": "comparison",
  "columns": [
    {"key":"metric","label":"维度","role":"label"},
    {"key":"value","label":"结果","role":"value"},
    {"key":"comment","label":"评价","role":"note"}
  ],
  "rows": [
    {"metric":"ROE","value":"13.4%","comment":"中上"}
  ]
}
```

要求：

- 每个 row 的键必须与 columns 的 `key` 完全一致。
- 允许 role：`label` / `value` / `assessment` / `action` / `note` / `date` / `metric` / `scenario` / `unit` / `status`。
- 禁止模型指定列宽、CSS、tooltip、HTML。
- 长文本放 `note`，前端负责换行、折叠和移动端布局。

## 通用 Block

```json
{"type":"heading","level":3,"text":"标题"}
{"type":"paragraph","text":"正文","note":false}
{"type":"callout","tone":"info","title":"本章小结","body":"结论与操作含义","summary":true}
{"type":"bullets","items":["要点一","要点二"]}
{"type":"formula","latex":"...","substitution":"...","explanation":"其中 r 指...，取..."}
{"type":"metric_cards","items":[{"label":"指标","value":"数值","detail":"说明"}]}
```

`tone` 使用 `pos` / `warn` / `neg` / `info`。

### Formula

`model_analysis` 与 `valuation` 必须包含公式，`cross_market` 可选。`formula` 不得出现在质量、产业周期、仓位、预期收益等章节；不要为质量均分、周期判断、仓位比例合计、收益加总等简单算术单独建公式卡。所有 `formula` 必须同时包含：

- `latex`：只写含符号的通用公式，不放具体数字。
- `substitution`：将实际取值代入同一符号公式，并给出结果。
- `explanation`：一段自然语言，说明符号含义、数据来源、期间、单位和选择理由。
- `caption`：可选，用于补充计算顺序或边界。

不要使用“符号含义”或“取值依据”作为独立小标题。`explanation` 中涉及的符号必须在 `latex` 真实出现，且解释能追溯到卡片前述数据或引用来源。

## 仓位

```json
{
  "type":"position_tiers",
  "market":"A",
  "items":[
    {"level":1,"price":50,"trigger_type":"valuation","condition":"进入合理买入区","allocation_pct":30,"active":true},
    {"level":2,"price":46,"trigger_type":"evidence","condition":"财报确认逻辑未恶化","allocation_pct":30,"active":false},
    {"level":3,"price":43,"trigger_type":"stabilization","condition":"价格止跌且中枢未下修","allocation_pct":25,"active":false},
    {"level":4,"price":40,"trigger_type":"catalyst","condition":"基本面改善得到验证","allocation_pct":15,"active":false}
  ]
}
```

`allocation_pct` 只是计划买入内部的分批比例，四档合计 100。仓位章节展示触发类型、条件、触发价和节奏，不展示总仓位、目标仓位或最大仓位。

## 收益

```json
{
  "type":"return_stack",
  "market":"A",
  "items":[
    {"source":"dividend","label":"股息","value_pct":4.5},
    {"source":"growth","label":"增长","value_pct":4.0},
    {"source":"valuation","label":"估值修复","value_pct":5.0},
    {"source":"fx","label":"汇率","value_pct":0}
  ],
  "total_pct":13.5
}
```

`source` 只能为 `dividend` / `growth` / `valuation` / `fx`；前端按 source 决定颜色和交互。

## 溢价

```json
{
  "type":"premium_donut",
  "market_pair":["A","H"],
  "total_premium_pct":20,
  "items":[
    {"label":"股息税差","contribution_pct":10,"share_pct":50,"tone":"green"},
    {"label":"贴现率差","contribution_pct":6,"share_pct":30,"tone":"blue"},
    {"label":"市场分割","contribution_pct":3,"share_pct":15,"tone":"gold"},
    {"label":"残余","contribution_pct":1,"share_pct":5,"tone":"red"}
  ]
}
```

`share_pct` 合计 100；`contribution_pct` 是百分点贡献。

## 风险

```json
{
  "type":"risk_cards",
  "items":[
    {
      "scope":"market",
      "market":"A",
      "title":"风险名称",
      "severity":"high",
      "body":"风险传导",
      "mitigation":"跟踪与应对"
    }
  ]
}
```

`severity` 只能为 `high` / `medium` / `low`。共同风险用 `scope: "common"` 和 `market: null`。
